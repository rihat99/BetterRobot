# 0034 Python 3.12 is the floor and the development version

**Status:** Accepted (owner). **Date:** 2026-11-01

## Context
BetterRobot declares `requires-python = ">=3.10"` and ruff `py310`, pins `.python-version` to 3.11, and its former
CI workflow ran on 3.12. Its contract tests import `tomllib` (3.11 and later), so the declared floor cannot run the
tests. BetterHuman has no `.python-version`. BetterVideoReconstruction's environment runs 3.12. Python 3.10 reached end
of life in October 2026.

## Decision
We will use Python 3.12 as the floor, the development version and the only tested version in both libraries.

## Example
```toml
[project]
requires-python = ">=3.12"

[tool.ruff]
target-version = "py312"
```
```text
.python-version   3.12
```

## Consequences
One interpreter to test and one syntax level: `type` statements, `X | Y` unions and `tomllib` are all available. The
declared range matches the range that can run the tests. Cost: users on 3.10 or 3.11 cannot install the new major.

## Alternatives
Floor 3.11 with development on 3.12 and both tested: two interpreters to run for no known user of 3.11. Keep 3.10 and
test it: the tests already need 3.11, and 3.10 is past its end of life. The scientific Python community's SPEC 0
drops Python versions on a fixed schedule, which a 3.10 floor now violates. Lowering a floor later is a compatible
change.

## Compatibility
Breaks installs on Python below 3.12. Each release documents its supported Python range (8.10). Reversible: yes, a
lower floor is compatible.

## Enforcement
New `tests/contract/test_python_version.py` in each repository: `requires-python`, ruff `target-version` and
`.python-version` agree; the contract tests' own `tomllib` import runs on the declared floor.
